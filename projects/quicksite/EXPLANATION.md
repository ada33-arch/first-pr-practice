# QuickSite (كويك سايت) — What This Project Is

## The one-paragraph version

QuickSite is a bilingual (Arabic/English), self-serve page builder. A visitor
answers four plain questions — what they're building, which look they want,
what they offer, and how people reach them — and gets a real, working page
built live from their own words. No accounts, no backend, no logo upload.
The first two pages are free; every page after that is a fair one-time fee,
never a subscription.

## Why it exists

Most people trying to describe their own business freeze up in front of a
blank page. Four short, concrete questions are easier to answer than "write
your homepage" — and the system turns those answers into something that
already looks considered: a chosen accent palette, a clear headline, an
offer grid, and a way to get in touch. Because the output is a single static
HTML file the customer owns outright, charging a one-time fee (instead of a
subscription) is the only honest model — nothing about the page depends on
this service staying online.

## How it works, end to end

1. A visitor opens `pages/index.html` (the landing page) or goes straight to
   `pages/brief.html`.
2. They pick a page kind (website / landing / deck / portfolio) and one of
   nine fixed accent palettes, then answer four short questions in Arabic or
   English.
3. As they type, a live preview renders inside an `<iframe srcdoc>` —
   generated by the exact same function (`buildCustomerPage()` in
   `code/site.js`) that produces the final downloadable file, so the preview
   and the download can never disagree.
4. They download the finished page as one self-contained `.html` file, or hit
   send, which composes a WhatsApp message to the site owner with everything
   they answered (and optionally fires an n8n webhook in parallel — see
   `automation/`).
5. The first two pages a visitor builds are free, tracked in their own
   browser via `localStorage` — not enforced server-side, since there is no
   server. That honesty is documented on purpose in `docs/idea.md`.

## Why it's built this way

- **No backend, no accounts.** Everything runs as static files; the "server"
  is just WhatsApp plus an optional n8n workflow. This matches the pattern
  used everywhere else in this repo (see `projects/rentstore/`) — no build
  step, no framework, open a page and it runs.
- **One generator function, two consumers.** The live preview and the
  downloaded file are never allowed to diverge, because they're literally the
  same code path.
- **Nine fixed palettes, not a colour picker.** Each palette carries a full
  accessible ramp (light through dark, plus a pre-computed readable text
  colour) defined once in `content/data.js`, so there's nothing to get wrong
  per-project.
- **Arabic is a first-class language, not an afterthought.** RTL layout,
  Arabic-appropriate fonts, and correct typographic details (no
  letter-spacing or uppercase transforms on Arabic script) are baked into
  `design/styles.css` and `code/site.js` from the start.
- **The limits are named, not hidden.** No logo upload, only nine looks, a
  client-side (not enforced) free-page count, first-draft copy instead of
  professionally written text — all spelled out in `docs/idea.md` so nobody
  is surprised later.

## What's deliberately not built yet

Named plainly, the same way the rest of this repo names its gaps:

- **Taking real payment** for pages after the first two free ones — there's
  no payment link wired up.
- **A logo upload slot** — kept out on purpose until there's evidence anyone
  actually wants it, since file uploads bring their own security surface.
- **A real delivery mechanism** for a paid page, beyond the same WhatsApp
  handoff used for the free path.

None of that blocks what's here today: the four questions, the nine
palettes, and a working downloadable page, in both languages, with nothing
to configure. See `docs/idea.md` for the fuller reasoning and `README.md`
for how to run and edit the project.
